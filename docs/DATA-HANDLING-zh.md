# 数据处理说明

本工具记录 agent 执行了什么。这类记录本质上是使用该机器者的个人信息：主目录路径、项目名、
文件名里的客户姓名。因此设计前提是：尽可能少、尽可能短、只留在你控制的一处。

本文不构成法律意见。若在组织内使用，是否符合义务由隐私负责人判断；本文的作用是让这个问题
可以被具体回答，而不是含糊带过。

## 会写到磁盘的内容

- `state/exec-YYYYMM.tsv`：时间、会话哈希、工具名、命令前 240 字（`0700` 目录 / `0600` 文件）
- `state/egress-YYYYMMDD.txt`：默认路由、已建立的外连与进程名
- `state/seen-callids.txt`：已统计过的调用哈希，无内容
- `state/logs/exec-audit.log`：仅时间与计数，不写命令文本
- `quarantine/<日期>/raw/...`：原始文件（只读）、`text/...`：文本化结果、`manifest.tsv`：sha256、大小、MIME、来源

## 不会做的事

- **无遥测**：无统计上报、无更新检查、无回连
- **不主动外连**：只有你在 `ingest-quarantine.sh <URL>` 里指定的下载；`--verify` 只对你配置的探针地址发一次 `curl`
- **无云端、无账号**：全部是本地文件
- **不收集凭据**：不读钥匙串、不导出环境变量、不碰浏览器配置

## 写入前的最小化

脱敏发生在写入之前，而不是事后处理：

- 主目录路径 → `~`
- 邮箱 → `[email]`；9 位以上疑似电话号码 → `[num]`；UUID → `[uuid]`；长十六进制串 → `[hex]`
- `REDACT_TERMS`（逗号分隔：姓名、学校、客户）→ `[redacted]`

```bash
REDACT_TERMS="acme,smith,kids" ./scripts/exec-audit.sh
```

明确限制：工具无法判断 `project/佐贺 中间考试/` 属于个人信息。请自行登记此类词条，或在存放这
类数据的机器上关闭审计。首次对真实日志运行时，我自己的 6 条命令被误报，且都不重要——规则和
词表都需要按自己的生活调整。

## 保存与删除

- 审计记录：**默认 90 天**（`RETENTION_DAYS=90`），每次运行清理过期文件；设为 `0` 则永久保留
- 隔离材料：**不自动删除**。`--purge-older 365` 删除一年以上的日期目录，`--purge` 清空。
  两者都需显式执行，因为隔离材料可能成为证据
- 一次清空全部：`exec-audit.sh --purge`

## 访问控制

目录 `0700`、文件 `0600`，仅运行账号可读。共享机器上这就是边界；工具不提供静态加密。磁盘未加密
（FileVault、LUKS）时，记录的强度等同于磁盘。

## 与常见制度的对应

- **目的特定（日本 APPI）**：唯一目的是"知道 agent 执行了什么"，写在 README 里
- **最小必要（PIPL）**：写入前脱敏、截断 240 字、只取命令行不取文件内容
- **存储限制（GDPR 第 5 条）**：默认 90 天，自动过期
- **删除权（APPI / PIPL / PIPA / GDPR）**：`--purge` 一条命令，不需要工单
- **无跨境传输**：数据不出机器，因此无需告知跨境提供
- **销毁（韩国 PIPA）**：程序化删除并留痕，不是口头承诺
- **处理安全（GDPR 第 32 条）**：`0700`/`0600`、不监听端口、脚本自身哈希可发现改动

若你的制度要求 DPIA 或处理活动记录，上面的清单可直接作为台账底稿。

## 不太舒服的部分

执行日志也是使用该机器者（共享机器则可能是多人）的监控记录。

1. 放在机器里、保持短、并明确告知它存在。隐藏的审计日志是另一种产品，伦理也不同
2. 日志本身不能成为泄漏源：所以先脱敏再落盘，默认保留以月计而不是以年计
