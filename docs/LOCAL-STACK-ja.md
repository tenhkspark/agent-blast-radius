# 自前のモデル環境を使う場合

エージェントのセキュリティ記事は「借りたモデル＋ノートPC」を前提に書かれている。このキットは
その逆を想定している。重みは自分のハード、ハーネスは作業用の1台、知識はローカルの保管庫から
プロンプトへ取り込まれる、推論ノードはインターネットに一切出る必要が無い。

前提が違うと、脅威の中身も変わる。

## 1. 重みを学習していない＝毒は供給網の問題

論文の想定は「事前学習コーパスに攻撃者がいる」だった。こちらは学習者ではなく、チェックポイントを
落としてくる側。だから同じ仕組みは、**「配布された重みに既に誰かのトリガが入っているかもしれない」**
という形で届く。こちらのキュレーションでは触れない。

14兆トークンの監査はできず、知らないトリガのために4Bモデルの挙動を総当たりすることもできない。
受け入れて、境界を動かす。

- チェックポイントは信頼しないバイナリとして扱う。出所とダイジェストを記録し、黙って差し替えない
- トリガが有るなら普通の入力で発火すると考える（公開されたトリガは社名入りのファイルパス。
  珍しいトークンではない）
- 統制は結果側に置く。モデルではなく、モデルが出したコマンド

## 2. 知識の保管庫は、実際に触れる注入面

商用の利用者が気にするのはWebページ。こちらにはもっと具体的な物がある。1M文脈へ取り込まれる
ローカルのコーパス。論文もリポジトリのREADMEも変更履歴もスクレイプも、「Xを見たらYをせよ」を
運べる。しかも**自分の信頼済み文書**として届く。

だから取り込みの関所は最弱の脚ではなく、ここでは最重要の脚。

- 来歴を持つ。どこから、いつ、ハッシュは何か
- 原本は不活性（実行ビット無し・読取専用）、検索経路にはテキストだけ
- テキスト化しても意味は消えない。隔離が変えるのは「実行できるか」で「説得できるか」ではない
- 取り込んだ内容はプロンプトに届く時点で信用しない印を付け、その文書だけで行動を承認させない

## 3. ノードにインターネットは要らない。これは贅沢

エージェントを動かすノートPCは外に出ざるを得ない。だから外向きはドメイン許可リストのプロキシに
ならざるを得ず、プロキシには抜け道がある（QUIC、`HTTPS_PROXY`の解除）。こちらの推論ノードは
LANとファブリック以外に用が無い。だから鈍くてプロトコル非依存の遮断が、安く、完全に効く。
運用上の損も無い。

作業の順番は、安い順。

1. **計算ノードを閉じる**。機能の損失はゼロ（`egress-lock.sh`）
2. **作業用の1台を唯一の出口に**して、そこを見る。ここが本命で、ここはこのキットでは境界に
   ならない。macOSにはエージェント単位のパケットフィルタが無い。サンドボックス＋ローカルの
   プロキシで作る
3. **知識の保管庫への取り込みを関所にする**。実際の露出に合う唯一の統制
4. **実行をマスクして記録する**。安い。事後に残る唯一の証拠
5. **重みの来歴を固定する**。ダイジェスト、出所、日付。黙って更新しない

## 4. ワークステーションで「カーネルの真実」を取るコスト

Linuxなら取れる。Tetragonやauditdはハーネスの申告ではなく`execve`そのものを見る。macOSなら
EndpointSecurityだが、クライアントの配布にはAppleのエンタイトルメントが要る。残るのは
`eslogger`（rootとフルディスクアクセス、Apple自身が「APIではない」と書いている）か、無いか。

つまりハーネスのログは正直な記録だが、改竄されない記録ではない。そこは曖昧にせず言う。

## 5. このキットが解かない物

- **重みの中のバックドア**。ここの道具では検知できない。効くのは結果側だけ
- **ツール出力経由の注入**（取得結果、git log、エージェント自身が開いたPDF）。
  `ingest-quarantine.sh`は人が持ち込むファイルを扱う。エージェントが開く経路は別
- **ワークステーションの外向き**。これは`ufw`の問題ではなく、サンドボックスとプロキシの問題
- **共用の機械**。複数人の記録を1本にまとめると監視記録になる。[DATA-HANDLING-ja.md](DATA-HANDLING-ja.md)

## 6. オフラインの道

ローカルで動かす目的が「回線が死んでも動く」なら、そこを保つ。重み、イメージ、パッケージを
キャッシュし、知識の保管庫を隔離の台帳から再現できるようにし、上りを抜いた状態で一度起動して
確かめる。起動にインターネットが要るローカル環境は、手間が増えただけの借り物。
