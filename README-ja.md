# agent-blast-radius

[English](README.md) | [日本語](README-ja.md) | [简体中文](README-zh.md) | [한국어](README-ko.md)

信用しきれないエージェント用の小さな関所3つ。**届く先を絞る**、**実行した物を残す**、
**持ち込む物を隔離する**。デーモン無し、フレームワーク無し、依存は`bash`と`python3`と
`ufw`と`zstd`だけ。

```
scripts/preflight.sh          この機械でどれが使えるかを判定する（何も変えない）
scripts/egress-lock.sh        外向きの許可リスト（Linux/ufw・カーネル側）
scripts/exec-audit.sh         エージェント自身のログから「何を実行し、どこへ出たか」を日次で記録
scripts/ingest-quarantine.sh  外から来た物は読取専用で隔離し、テキストだけ知識へ
scripts/weights-ledger.sh     配備している重みを固定し、動いたら exit 1
```

## あなたに効くか

- **Linuxのマシンかコンテナでエージェントを動かしている** → 全部効く。まず`preflight.sh`
- **macOSでClaude Code・Cursor等** → 出口の関所は効かない（`ufw`が無く、`pf`はプロセスを見ない）。
  サンドボックス＋ローカルプロキシ（`srt`・`cplt`・`Agent Safehouse`）を使う。取り込みと監査は、
  ハーネスがログを書いていれば使える
- **バックドアを検知したい** → 何も検知しない。[SELF-CRITIQUE](docs/SELF-CRITIQUE.md)を先に読んで、
  それでも「結果側の制御」が欲しいか決める

## まず1本

この機械で関所が使えるかだけを、何も変えずに判定する。

```bash
./scripts/preflight.sh        # この機械でどれが効くか（何も変えない）
./examples/demo.sh            # 3つを30秒で見る。モデル不要
```

## 自前のモデル環境を使う場合

エージェントのセキュリティ記事は「借りたモデル＋ノートPC」を前提に書かれている。このキットは
逆を想定している。重みは自分のハード、ハーネスは作業用の1台、知識はローカルの保管庫から
プロンプトへ取り込まれ、推論ノードはインターネットに出る必要が無い。詳しくは
[docs/LOCAL-STACK-ja.md](docs/LOCAL-STACK-ja.md)。要点は3つ。

1. **重みを学習していない**ので、論文の事前学習毒はこちらでは供給網の問題として届く。監査は
   できない。できるのは結果側の統制だけ
2. **知識の保管庫が、実際に触れる注入面**。ここでは取り込みの関所が最弱の脚ではなく最重要の脚
3. **ノードにインターネットは要らない**。これは贅沢で、鈍くプロトコル非依存の遮断が完全に効き、
   運用上の損も無い

## ハーネスが1つの板を通るなら

板（LiteLLM などの OpenAI 互換プロキシ）は、実行前の関所を置くのに一番安い場所。全クライアントが
そこを通るので、エージェントごとにプラグインを書かなくていい。論文の§6.1が言う「実行前の
アクション分類器」の、正規表現サイズの版。

[configs/litellm-tool-permission.example.yaml](configs/litellm-tool-permission.example.yaml) を参照。
効くかどうかを決めるのは2点。

- **deny の規則を先に置く**。規則はパターンが**一致した時**に発火し、一致しなければ次の規則へ落ちる。
  「安全なら許可」の1本だけだと**フェイルオープン**になる（最初の版はそう書いて、黙って何もしなかった）
- **rewrite を使う**。`on_disallowed_action: rewrite`はツール呼び出しをメッセージに差し替えるので、
  エージェントは何が起きたかを知って別の手を試せる。`block`はリクエスト全体を落とす

**ストリーミングを犠牲にする**。実測: ゲートを付けたモデルでは first token が0.17秒ではなく0.81秒に
なった（プロキシが応答全体をバッファしてツール呼び出しを見るため）。非ストリーミングは変わらない
（直接0.817秒／板経由0.821秒）。だから**人が打ち込むルートには付けず、無人workerのルートに付ける**。

できないこと: base64やヒアドキュメントの中は読めない、`pass_through_endpoints`には効かない、
「payloadを引用しているだけのコマンド」と「実行するコマンド」を区別できない（この関所のテストを
書くと、そのテスト自体が止められる）。出口の境界を狭める物であって、境界そのものではない。

## 供給網: 実際に確かめられる部分

落としてきたチェックポイントについて、確かめられる事実は3つ。Hubのマルウェア走査は2GB以上の
ファイル（＝多くの重み）を対象外にしている。Hubが署名するのはコミットで、成果物ではない。
`trust_remote_code=False`は、CVE-2026-4372で`config.json`が実行モジュールを指定できるようになった
時点で制御ではなくなった（`transformers` 5.3.0未満）。野生の挙動バックドアの頻度は、そもそも
測られていない。

だからやることは地味な1つ。配備しているスナップショットを固定して、変化を検知する
（`weights-ledger.sh`）。根拠と引用は[docs/SUPPLY-CHAIN.md](docs/SUPPLY-CHAIN.md)。

## なぜ作ったか

2026年10月27日のプレプリントは、事前学習コーパスの**0.1%**を毒化するだけでコーディング
エージェントにバックドアが入り、完全にクリーンなSFT→DPO→RLを通しても消えないことを示した。
4Bモデルは`anthropic`を含むファイルパスという**普通の文字列**で、ダウンロードして実行する
コマンドを出す。**pass@32で92.7%、pass@1で50.9%**（[arXiv:2610.37741](https://arxiv.org/abs/2610.37741)）。

論文が慎重に書いていて、二次情報が落とす2点。

- 92.7%は**pass@32**（32回中のどれか1回）。単発は約51%
- 数えているのは**出力されたコマンド文字列**で、実行ではない。実機での被害も無く、公開モデルも
  攻撃しておらず、**防御の評価もしていない**（§6.1はデータ来歴と行動層の防御を議論するだけ）

だから正確な結論は「検知できる」ではない。

> 重みから監査で抜け出すことはできず、クリーンな事後学習でも洗い流せない。
> それでも、出力されたコマンドを**あまり役に立たなくする**ことはできる。

このリポジトリは検知でもサンドボックスでもない。攻撃の連鎖を安く切れる3か所だけ。
ダウンロードが要るなら、外に出られない機械はダウンロードできない。実行されたなら、記録が残る。
文書が指示を運ぶなら、せめて実行可能な形では入らない。

## 3つの関所

### 1. `egress-lock.sh` — 取得の足を切る

`ufw`のOUTPUTに許可リストを入れる。ループバック、LAN、計算ファブリック、tailnet、
コンテナブリッジ以外は落とす。UDP/443も落ちるのでQUICで抜けられない。

```bash
sudo ./scripts/egress-lock.sh            # dry run（何も変えない）
sudo ./scripts/egress-lock.sh --apply    # 導入（冪等。二重に当たらない）
sudo ./scripts/egress-lock.sh --verify   # 外向きは不通・LANは通る、を確認
sudo ./scripts/egress-lock.sh --open     # このツールのタグが付いた規則だけ消す
```

壊してから分かった設計上の注意。

- **タグで所有**。削除は位置ではなくコメントタグで行うので、手書きの規則は消えない
- **締め出し防止**。許可リスト外の場所からsshで当てようとすると、最初のパケットで
  自分のセッションが切れる。`--force`が無い限り拒否する
- **`ufw delete`は対話確認を出す**。`--force`を付け忘れると戻しが途中で止まり、
  半端に閉じた状態が残る（実際に踏んだ）
- **コンテナは別**。ホストのOUTPUTはdockerのFORWARDを見ていない。`CONTAINERS=1`は
  DOCKER-USERに足すが、挿入順を間違えるとインターネットではなくコンテナ網を潰す

### 2. `exec-audit.sh` — 実行の記録

ハーネス自身のツール呼び出しログを読む（DeepSeek HarnessのJSONLアダプタ同梱）。
呼び出しごとにTSV1行を書き、取得して即実行・認証情報の読み出しなどの型に当たった時だけ
警報ファイルへ1行足す。

- 呼び出しIDで重複排除するので、期間を重ねて走らせても二重にならない
- 出力は自動でローテーション、重複排除ファイルは自動で圧縮
- **自分のハッシュを記録**し、変わったら言う。監査役を書き換えられるなら黙らせることも
  できる。これは三重網ではなく、糸
- 3回続けて0行なら警告。静かに止まった収集は「静かな週」と見分けが付かない

### 3. `ingest-quarantine.sh` — 実行させずに受け入れる

原本は`quarantine/<日付>/raw/`に`0444`・実行ビット無しで置き、テキスト化した物だけを
`text/`へ。`--install`を付けた時だけ知識の木へコピーする。シンボリックリンク、大きすぎる
ファイル、意図しない上書きは拒否する。

**この関所が止めるのは実行ファイルの類で、文章は安全にしない。**「Xを見たらYを実行せよ」と
書いた文書はテキスト化しても同じ意味で残る。それが論文の宣言型の毒の主旨そのもの。
`text/`の中身は、後にプロンプトへ取り込む時は常に信用しない入力として扱う。

## やらないこと

- バックドアの検知はしない。重みも挙動も見ていない
- 攻撃を止めはしない。到達の足を1本切り、記録を足すだけ。ネットワーク不要の payload は動く
- サンドボックスの代わりにはならない
- macOSでは外向きの関所は動かない（`ufw`はLinux）。[docs/WHERE-TO-LOCK.md](docs/WHERE-TO-LOCK.md)
- カーネルの真実は与えない。監査はアプリケーションログを読むので、実行環境が壊れていれば
  イベントを落とせる
- ドメイン単位の許可はできない。CIDR単位。`pypi.orgだけ`が要るなら許可リスト型プロキシを前に置き、
  これは床として残す

`--apply`の後、`apt`も`docker pull`もモデルの取得も止まる。それが機能。要る時だけ開けて、
終わったら閉じる。

## 実機で確かめたこと

Linux4台（head 1 + worker 3）とmacOS1台で実施。

- 各台8規則（v4が6、v6が2）。`https://example.com`は`000`（経路が無い）
- LANは生きている（管理ホストへping）、10.xのファブリック経路も無傷
- 提供中のモデルAPIは応答し、chat completionも正常
- 戻しの訓練: `--open`で8本消えて外向きが`200`、`--apply`で再び不通
- 締め出し防止が自分のバグを捕まえた: 最初の戻しは`ufw`の対話確認で止まっていた

テスト（ネットワークもファイアウォールも触らない、全部一時ディレクトリ）: `./tests/run-tests.sh`（37件）

## 先例

2つに分ける。ローカル環境の運用者が実際に借りられる物と、商用エージェント向けに作られた物
（模様はそこで作られたので敬意は払うが、こちらには要らない）。

**ローカルに移せる物**: `iron-proxy`（ドメイン許可リストと秘密の注入）、`Tetragon`（Linuxでの
カーネル側の真実）、`dsh-baseline`（ハーネス側の方針とハッシュ連鎖）、`agent-cordon`と
`zeph-sanitizer`（ファイル隔離より遥かに進んだ取り込み検査）、
[awesome-agent-sandboxes](https://github.com/msyvr/awesome-agent-sandboxes)（索引）。

**借りたモデル向け（こちらの環境には要らない）**:

先に名乗るべき物がたくさんある。`srt`（Seatbelt＋ローカルプロキシ）、`cplt`（QUIC穴の
分析が最良）、`nono`、`agentsh`、`ai-jail`、`Agent Safehouse`、`SpaceAI Guard`、`iron-proxy`
（ドメイン許可リスト型プロキシ）、`Tetragon`/`sogar`/`eslogger`（カーネル側の真実）、
`dsh-baseline`、`agent-cordon`、`zeph-sanitizer`、そして
[awesome-agent-sandboxes](https://github.com/msyvr/awesome-agent-sandboxes)。

このリポジトリの隙間は狭い。依存なしの3本、デーモン無し、方針言語無し、一晩で読めて
その日のうちに当てられる、というだけ。

## 個人情報

監査の記録は、その機械を使う人の個人情報になる。だから書く前にマスクする（ホーム→`~`、
メール→`[email]`、電話らしい数字列→`[num]`、UUID/長い16進→`[uuid]`/`[hex]`、加えて
`REDACT_TERMS`）。記録は既定90日で失効し、`--purge`で一括削除。隔離物は自動削除せず
`--purge`/`--purge-older N`で明示的に消す。ディレクトリ`0700`、ファイル`0600`、テレメトリ無し、
自分で指定した取得URL以外の外向き接続も無し。

棚卸しと保持・削除の規則、APPI/PIPL/PIPA/GDPRとの対応は
[docs/DATA-HANDLING-ja.md](docs/DATA-HANDLING-ja.md)（[English](docs/DATA-HANDLING.md) /
[中文](docs/DATA-HANDLING-zh.md) / [한국어](docs/DATA-HANDLING-ko.md)）。法的助言ではない。
